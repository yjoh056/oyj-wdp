01

프로젝트 분류 기준 재정립

문제 발견

포트폴리오 사이트 자체를 새 프로젝트로 추가하려다, "이걸 대체 어느 카테고리에 넣어야 하나"라는 분류 기준 자체의 공백을 발견했다. 기존에는 프로젝트가 만들어진 출처(회사·학원)로만 나뉘어 있었다.

검토한 방안

직접 코드로 퍼블리싱했는지를 기준으로 나누는 "만든 기준"과, 어디서 한 작업인지를 기준으로 나누는 "출처 기준" 두 방향을 비교했다.

선택

포트폴리오를 보는 사람(채용 담당자)이 궁금한 건 "이 사람이 무엇을 만들 수 있는가"라고 판단해 만든 기준을 선택했다.

결과

Publisher Project / Designer Project / UI-UX Case Study 세 카테고리로 재정의하고, QR 출입 키오스크를 포함한 프로젝트 카드 전체를 새 기준에 맞게 재배치했다.

02

포트폴리오 사이트를 프로젝트로 편입

문제 발견

이미 올라가 있는 프로젝트들은 전부 AI와의 협업 없이 진행한 작업들이라, 실무에서 AI를 어떻게 활용하는지 보여줄 사례가 하나도 없었다.

검토한 방안

AI 협업을 보여주기 위한 새 프로젝트를 따로 기획해서 추가할지, 지금 진행 중인 작업을 그대로 소재로 쓸지 고민했다.

선택

마침 이 사이트 자체를 Claude와 협업하며 고쳐나가고 있었기 때문에, 그 과정 자체가 가장 진솔한 소재라고 판단해 포트폴리오 사이트를 프로젝트로 편입하기로 했다.

결과

Publisher Project 02로 추가하고, "요구사항 정의 → AI 구현 지시 → 결과 검증 및 반려·재지시"라는 협업 방식을 카드 설명에 명시했다. 지금 보고 있는 이 페이지도 그 협업 기록의 일부다.

03

Project 서브메뉴 추가

문제 발견

프로젝트 카테고리가 늘어나면서 PROJECT 섹션 전체 길이가 길어졌고, 원하는 카테고리를 찾으려면 계속 스크롤해야 하는 불편이 예상됐다.

검토한 방안

사이드 내비게이션을 지금 그대로 둘지, 카테고리별로 바로 이동할 수 있는 하위 메뉴를 추가할지 검토했다.

선택

상단 GNB와 사이드 내비게이션 양쪽에 Publisher·Designer·UI/UX 카테고리로 바로 이동하는 서브메뉴를 추가하기로 했다.

결과

마우스 오버·클릭 시 펼쳐지는 서브메뉴 UI를 구현해, 데스크톱과 모바일 내비게이션 양쪽에 동일하게 적용했다.

04

화면설계서 뒤로가기 UX 개선

문제 발견

직접 화면설계서 페이지를 열어보고 "포트폴리오로 돌아가기"를 눌렀더니, 보고 있던 카드가 아니라 PROJECT 섹션 맨 위로 이동해 다시 스크롤해야 하는 불편을 발견했다.

검토한 방안

원인을 살펴보니 모든 화면설계서 페이지의 뒤로가기 링크가 섹션 공용 앵커 하나를 공유하고 있었다. 카드마다 개별 앵커를 부여하는 방식을 검토했다.

선택

프로젝트 카드 전체에 고유 id를 부여하고, 각 화면설계서 페이지의 뒤로가기 링크가 자신이 속한 카드로 정확히 돌아가도록 수정하기로 했다.

결과

어떤 화면설계서를 보고 돌아와도 원래 보던 카드 위치로 바로 복귀한다. 고정 내비게이션에 가리지 않도록 여백도 함께 조정했다.
